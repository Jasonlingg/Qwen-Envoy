**Recommended measurements.** Pin hardware, runtime/version, base-model and Envoy v5 revisions, inference quantization, adapter loading, tokenizer/chat template, sampling and cache settings. QLoRA training does not establish inference precision or speed. Count approximately 4,000 *rendered input tokens* and all generated tokens—including thinking tokens—toward the 200-token workload; Qwen3 supports distinct thinking modes. [Qwen3-8B model documentation](https://huggingface.co/Qwen/Qwen3-8B)

Record request-level timestamps across the MCP client and server:

- **Queueing:** server arrival to first scheduling, plus any later scheduling/preemption stalls. Compare one request with two arriving together; two concurrent clients do not guarantee simultaneous GPU execution.
- **Prefill:** time processing uncached prompt tokens. Measure client time to first token (TTFT) separately: it also includes transport, tokenization, queueing and first-token delivery.
- **Decoding:** first-to-last-token duration and inter-token gaps. For exactly 200 output tokens, average post-first-token time is `(last − first)/199`. Record each request’s completion time and when **both** finish.
- **Cold start:** activation-to-ready and activation-to-first-completed-answer, separating model/adapter loading, runtime initialization and compilation/warmup where observable. Keep these separate from warm requests and from an empty prefix cache.
