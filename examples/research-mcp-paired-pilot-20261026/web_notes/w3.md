# W3: For two concurrent Qwen3-8B readers, focus next latency test on prefix caching or speculative decoding?

Research window (UTC): 2026-10-26T20:33:27Z to 2026-10-26T20:35:29Z. The common start is the pilot start; all five questions were in scope throughout.

Recommendation: Test prefix caching first if the two readers reuse an identical serialized system/paper prefix; make prompt-prefix identity and cache-hit rate the first measurements. If real traffic shares little prefix or decode dominates, test speculative decoding next.

## Source-linked claims

- vLLM prefix caching reuses KV cache for matching prefixes and reduces prefill work, but it does not reduce decoding time. [Introduction and Limits sections](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)
- vLLM documents speculative decoding primarily as a way to reduce inter-token latency for medium-to-low-QPS, memory-bound workloads. [Introduction](https://docs.vllm.ai/en/latest/features/speculative_decoding/index.html)
- A serving study found speculative-decoding speedups often shrink as server load rises and depend on draft acceptance and model sizes. [Abstract, lines 16-18](https://arxiv.org/abs/2605.15051)

Baseline: Same Qwen3-8B serving stack with prefix caching disabled and speculative decoding disabled, two concurrent clients, frozen prompt and output-length distribution.

Cheapest matched test: On the same machine and two-client replay, alternate caching off/on after warmup with the same exact prompt bytes and decoding settings. Include a shared-prefix stratum and a deliberately distinct-prefix stratum. Record TTFT, inter-token latency, end-to-end p50/p95, output tokens, throughput, VRAM, and cache hits.

Decision rule: Pursue prefix caching if the shared-prefix stratum yields at least 20% lower median TTFT and at least 10% lower median end-to-end latency, with p95 end-to-end no worse than 10%, and the real workload exhibits at least 50% prefix reuse. Otherwise test speculative decoding under the same two-client load. These are predeclared local thresholds.

Uncertainty: Actual prompt serialization, prefix overlap, prefill/decode split, hardware, and baseline latency are unset. Prefix caching offers no expected benefit for divergent prefixes; no speedup is assumed.
