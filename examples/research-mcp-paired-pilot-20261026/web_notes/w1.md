# W1 — supervised examples or another GRPO run?

**Question:** With no new GPU budget yet, should the next investment be more supervised examples or another small GRPO run?

**UTC interval:** 2026-10-26 20:36:07 UTC to 2026-10-26 20:37:24 UTC

**Recommendation:** Spend the next scarce budget on human review of answer support and a small number of failure-targeted, verified supervised trajectories; defer another GRPO run. This is a priority for evidence collection and data curation, not a claim that adding examples will necessarily improve the model.

The supplied pilot context says the reader has 35 replay-verified trajectories, v5 SFT cut recorded execution-error episodes from 22 to 1 on 40 development questions, and provisional supported-answer passes remained 3/20 for base and v5 on answerable cases. These figures are task-provided context, not findings from the three papers. They imply that another training run should wait for a credible answer-quality signal.

## Source-linked claims

- DeepSeekMath GRPO replaces PPO’s learned value-model baseline with scores from multiple outputs to the same question. [§4.1.1, lines 263–266](https://arxiv.org/html/2402.03300)
- DeepSeekMath’s reported RL phase used about 144,000 math questions and sampled 64 outputs per question. [§4.2, lines 312–314](https://arxiv.org/html/2402.03300)
- ReTool trained a code-integrated cold-start SFT model before applying RL with interleaved code execution. [§2.1, lines 55–60](https://arxiv.org/html/2504.11536)
- ReTool used a rule-based final-answer correctness reward against ground truth and did not include code executability in that reward. [§2.3.1, lines 81–86](https://arxiv.org/html/2504.11536)
- DeepSeek-R1’s authors say reward reliability is central to RL and that reliable signals are hard to construct for open-ended tasks. [§G.1, lines 1600–1603](https://arxiv.org/html/2501.12948)
- DeepSeek-R1’s authors report reward hacking with a helpfulness reward: reward rose while Codeforces performance fell. [§B.5, lines 1175–1178](https://arxiv.org/html/2501.12948)

The inference is that this reader currently has an execution-reliability gain but no demonstrated supported-answer gain, and its answer-support reward is not shown to be sufficiently faithful for GRPO. GRPO remains a plausible later experiment; the papers do not establish that SFT wins for this reader.

## Cheapest matched test and decision rule

**Hypothesis:** A small set of human-reviewed trajectories that demonstrate evidence selection and supported answers will improve supported-answer quality more cheaply than an immediate GRPO run. **Expected signal:** previously unsupported or incorrect answers become supported on paired questions without eroding execution reliability.

**Simpler baseline:** Before training, compare the current v5 checkpoint with the same checkpoint given a compact, fixed few-shot prompt containing reviewed tool-use-and-evidence demonstrations. Keep the question set, corpus, decoding, and scoring identical; exclude test-question content from demonstrations.

**Matched test:** On the same frozen 40 development questions, blindly review answer support for the 20 answerable items, and record execution-error episodes, latency, and inference cost for all 40. Compare current v5 with the no-training few-shot baseline using paired question-level results. Reserve separate, unseen questions before any later SFT model is promoted; do not call the 40-question development result a held-out effect, or treat source span presence or replay success as answer correctness.

**Decision rule:** Predeclared development-pilot gate, not a significance claim: prioritize preparing a small targeted SFT dataset if the reviewed few-shot baseline improves supported-answer passes from v5’s 3/20 to at least 6/20 on the same answerable development items, loses none of the three currently passing items, keeps execution-error episodes at or below 1/40, and keeps median latency and inference cost each at or below 1.20× v5. Train when compute exists, then require a separately reserved matched held-out test before claiming model improvement. Reconsider GRPO only after a blinded audit shows a reliable reward that tracks supported-answer judgments on unseen outputs and a small matched rollout shows nontrivial reward variation; the numerical agreement/variation threshold for that future GRPO gate is explicitly unset pending labeled samples.

**Uncertainty:** The 3/20 supported-answer counts are provisional, the sample is small, and no causal comparison of additional SFT versus GRPO exists for this specific Qwen3-8B reader. The cited math/tool-RL studies use different tasks, model scales, and verifiable ground-truth rewards, so their gains do not transfer directly. The proposed +3/20 threshold is a practical pilot rule rather than a statistical confidence bound.
