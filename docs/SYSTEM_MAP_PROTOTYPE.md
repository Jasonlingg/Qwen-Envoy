# Systems-map prototype

The local `/lab/map` page tests whether a visual system model helps a person
reason about a research or building project. It is a usability prototype beside
the existing question desk, not a measured Qwen capability or a replacement
for the weekly digest and model-improvement gates.

## Transformer architecture learning case

Run `python scripts/launch_transformer_map_demo.py --port 8770` and open the
printed URL. This disposable map traces the **original encoder–decoder
Transformer** from input tokens through the encoder and from previous output
tokens through the masked decoder, cross-attention, and output prediction.
Select a connection to inspect its source passage from [*Attention Is All You
Need*](https://arxiv.org/html/1706.03762). The map is a learning aid: tracing
one predicted token makes the data flow and the decoder's causal mask easier to
explain than a list of component names.

When the optional GPT paper import is available, preview the manually curated
proposal for a **decoder-only** language-model variant, sourced to [the original
GPT paper](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf).
This is a later architecture variant, not the same encoder–decoder design or a
contradiction in the sources. The map and proposal are human-authored examples;
Qwen does not generate them, and the launcher makes no model or GPU calls. It
fetches and freezes the 2017 paper on launch. If `pypdf` or the 2018 paper is
unavailable, the original map still runs and the optional comparison is
skipped. The temporary source copies and map are removed when the launcher
exits.

## Evidence-linked research case

Run `python scripts/launch_research_map_demo.py --port 8768` and open the URL it
prints. This disposable case asks whether more SFT improves Qwen's
source-supported answers. It attaches three actual project reports as frozen
Markdown files, starts with a narrow QASPER result supporting the belief, and
stages a **manually curated** update for review. The update adds conflicting
continuation and synthetic-vault results, an abstention tradeoff, and a concrete
held-out vault test. Select the central belief arrow to inspect the exact
supporting and challenging passages. Preview the proposed map, then accept or
dismiss it; acceptance creates a dated revision you can compare with the
original.

The QASPER comparisons used different question sets and must not have their
pass counts pooled. The synthetic-vault answer review is provisional and not
independent human review. The proposed change is a workflow mock, **not a Qwen
output**. The source spans are checked against frozen report copies, but the
relationship assessments and next test are human-authored interpretations.
No model or remote API is called, and the temporary demo vault is removed when
the launcher exits.

## What to try

Open the illustrated Qwen pipeline, move a block, and select two kinds of
connection: a designed data flow and a hypothesis about training quality. The
illustration is curated example content, **not generated by Qwen** or evidence
that the whole pipeline runs end to end. Then start a question in `/lab`, open
its map, add and connect a few blocks, attach a source passage to a connection,
and save a revision. Return to an earlier revision to see what changed.

The map is a working model. A line labeled *documented* carries an inspectable
source receipt; its exact quotation establishes provenance, not that the
interpretation is true. A *hypothesis* is an unverified relationship. Layout
position is presentation, not evidence. Source imports and map revisions stay
outside the reviewed Obsidian library. Neither opening nor saving the map
calls a model or writes a reviewed note.

## Usability experiment

**Hypothesis:** a person can understand the project's components, identify an
uncertain relationship, and see how the model changed more easily on a small
evidence-linked map than on the linear question page.

**Signal:** on one real question with a few sources, the user can explain a
selected connection, find the passage behind it, identify what remains a
hypothesis, and recover the prior map after a revision. Ask how much manual
editing the map required and whether it changed the next test they would run.

**Decision rule:** if the map mainly duplicates source cards and takes longer
to understand or update, keep the question desk and use diagrams only for
questions with meaningful relationships. Successful drag-and-drop or valid
source references alone do not establish product usefulness.

## Model boundary

The current trained Qwen checkpoint has **not** generated these maps. The
existing Qwen investigator searches a frozen vault or paper corpus and returns
a proposed answer with exact source spans; newly uploaded files are not yet in
its investigation corpus. A separate, reviewed pilot must compare base and
trained Qwen on the same source-to-map questions before adding a button that
claims Qwen can construct useful system diagrams. A renderer can lay out
validated nodes and edges deterministically; source-span checks cannot prove
causal relationships.
