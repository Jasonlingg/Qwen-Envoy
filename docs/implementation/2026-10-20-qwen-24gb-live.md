# Native Qwen research workflow on a 24 GB GPU

The cheaper GPU works. The research worker did not produce usable evidence in
this test. A fresh native host called the full research MCP, observed the worker
failure, read cached passages directly, and saved/retrieved an experiment brief.
This demonstrates the connection and failure path; it does not demonstrate
successful Qwen evidence extraction, a quality win, or a trained-model gain.

## Integration fixes and unsuccessful attempts

The initial native attempt exposed two simultaneous MCP startup processes. The
old exclusive audit-file creation made one fail. The budget now persists
reservations under a process/thread lock and fsync; starting another process or
restarting cannot restore spent requests. A test with eight attempts across four
processes against a three-request budget allowed exactly three submissions. A
zero-answer native preflight confirmed both processes connected successfully.
The runner now waits for connected servers before launching an answering turn.

The next attempt reached the tools but exposed my incorrect `v3` paper pin;
that revision does not exist. The corrected `v2` was verified and fetched before
the final attempt. Both earlier answering attempts made zero Qwen requests and
remain preserved. They are not silently replaced by the final run.

During the final run I found another compatibility bug: the local Transformers
version returns a BatchEncoding by default, whose length is two fields rather
than the number of tokens. Raw audit prompt counts of two are invalid. All
eight payloads were recounted with explicit token IDs, exactly matching provider
usage; their actual lengths were 1,325–2,141, below the 7,168 input limit.
`b83595c` now requests a flat token-ID list and rejects any other shape. The
completed run predates that fix; its live source hashes are recorded. No extra
paid inference was made to retest the fix. The request ledger, eight-step limit,
output limit and server context bound remained in force during the run.

The transport also now records a returned job ID immediately after submission,
so a process failure during cold-start polling leaves an attributable job.
It never automatically resubmits an uncertain inference request. Request/token
limits are not a provider dollar cap.

  three existing SWIG deprecation warnings.
- Independent read-only review found no actionable correctness/security issue;
  its 19 narrow tests passed. Its stale-report finding is corrected here and
  in the initial smoke document. A reporting follow-up also corrected the
  distinction between the TypeError and later duplicate-code rejections.
- All ten protected-file hashes remain unchanged.

Current behavior lets a full MCP host call the optional Qwen reader and inspect
its failures, use direct passages, and persist an evidence-linked draft. The
worker needs better tool-use reliability before it is useful for this question.
This one development case cannot identify whether the cause is prompt fit,
training transfer, task breadth, or model capability. It is not a Nemotron run,
fixed-action replay, held-out evaluation, or base-versus-trained comparison.
