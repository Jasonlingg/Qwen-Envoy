**Memory looks plausible, subject to measurement.** With one model replica sharing weights across two requests, approximate 16-bit weight storage is 8.0 GB for Qwen and 7.6 GB for Phi. At two sequences of 6,256 tokens, a conventional 16-bit KV cache is approximately **1.85 GB** and **1.64 GB**, respectively. Calculation: `2(K,V) × layers × KV_heads × head_dim × total_tokens × 2 bytes`, using the published configurations. These estimates exclude activations, prefill workspace, graph capture, allocator reserves and runtime overhead. They support trying unquantized weights first on 24 GB; they do not guarantee fit. [Qwen configuration](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/blob/1b4199c4f36b0cef378bfb12390c18780c18af4c/config.json), [Phi configuration](https://huggingface.co/microsoft/Phi-4-mini-instruct/blob/618e63e60172e9efa181cbfeee9d7012e5b2ad66/config.json).

Unknowns remain: exact 8B checkpoint and accuracy, GPU model, runtime/version, baseline precision, schema and field count, document preprocessing, acceptable accuracy loss, and latency target. Also unknown is whether “6,000 input tokens” includes instructions and schema. Count complete prompts separately with each tokenizer; allow overhead without silently truncating documents.

**Proposed matched pilot—do not execute yet:**

- **Data and baseline:** Use 20 development documents to freeze prompts and scoring, then 200 held-out, manually adjudicated documents shared across all three models. Include tables, identifiers, units, absent fields, conflicting values and evidence near document ends. Identify and pin the actual 8B baseline before comparing.
- **Controls:** Load models sequentially on the same GPU, each serving two simultaneous requests. Use a common compatible runtime/version, identical document text, schema and extraction instructions, model-native chat templates, greedy decoding and a 256-token output cap. Apply schema-constrained decoding consistently if supported by all three. Record precision; any quantized comparison is a separate configuration.
- **Measurements:** Report whole-document exact match, per-field exact match and precision/recall, invented values, omissions, unit/type errors, invalid JSON and output truncation. At concurrency two, measure p50/p95 end-to-end latency, time to first token, documents/second, peak device memory and failures. Exclude warm-up; disable cross-request prefix caching.
- **Decision rule:** As provisional thresholds, require the paired 95% confidence interval for document exact-match difference to stay above **−2 percentage points**, no observed increase in critical-field errors, no OOM or request failures, and at least **20% lower p95 latency** versus 8B. These thresholds need business acceptance; latency-SLA compliance remains unknown.
- **Stop:** Stop a configuration on OOM, unsupported execution or silent truncation. Otherwise stop after the fixed pilot. If uncertainty crosses the quality margin, retain 8B and defer replacement pending a larger evaluation.
