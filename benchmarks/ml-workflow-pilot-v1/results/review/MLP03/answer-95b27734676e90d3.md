**Defer fine-tuning. First test whether clearer instructions and better evidence resolve the failures.** The hypothetical baseline is 150/200 = **75% passing**. Of 50 failures, 40% lack evidence, 40% answer incorrectly despite visible evidence, and 20% violate the schema. These counts identify symptoms; they do not establish that training is the best remedy.

The 20 evidence-visible errors are plausible fine-tuning targets, but prompt ambiguity, distracting context, or incorrect reference answers remain possible explanations. RAG evaluation should distinguish retrieval quality from faithful use of retrieved material, as [RAGAs](https://aclanthology.org/2024.eacl-demo.16/) does. [RAFT](https://arxiv.org/abs/2403.10131v1) demonstrates that training with relevant and distracting documents can improve in-domain RAG; its benchmark results do not establish that your 300 unchecked examples would help.

**One diagnostic experiment: a paired, three-condition replay.** Once actual cases and logs exist, use all 50 development failures plus 20 randomly selected development passes as regression controls. Keep the 100 untouched evaluation cases sealed.

Freeze the checkpoint, runtime, decoding settings, corpus/index revision, context budget, and scoring rubric. Predeclare one revised prompt requiring evidence-grounded answers, appropriate abstention, and the exact output schema, with one independently authored valid example. Then compare:

| Condition | Prompt | Evidence |
|---|---|---|
| A: baseline | Current | Original retrieved context |
| B: inexpensive fix | Revised | Same original context |
| C: evidence diagnostic | Same revised prompt | Verified sufficient source excerpts |

For C, a domain reviewer should select authoritative excerpts containing the necessary facts, without inserting a reference answer. Fit them within the same context budget and record replacements. This tests performance with curated evidence; it does **not** estimate the gain achievable by a particular retriever.

This bounded design requires at most **210 outputs**, with no training. A→B measures the prompt change under actual retrieval; B→C measures the additional benefit of curated evidence. It does not estimate every prompt–context interaction.

Score each output independently for:

- Answer correctness and support by the supplied evidence, using blinded domain review.
- Exact schema validity, using a deterministic validator.
- Joint pass: both content and schema pass.
- Paired rescues and regressions, reported separately for each original failure category and the pass controls.

Do not report this failure-enriched subset’s aggregate pass rate as population accuracy. Record latency and token usage to expose practical costs.

Use these **proposed screening thresholds**, rather than treating them as statistical guarantees:

- If B rescues at least **10 of the 30 evidence-visible/schema failures**, with no regressions among the 20 pass controls, prioritize the prompt fix.
- If C additionally rescues at least **10 of the 20 missing-evidence failures**, prioritize corpus coverage, retrieval, or context assembly. If authoritative evidence is absent from the corpus, address coverage first.
- I would move toward a **scoped fine-tuning pilot** if B provides little benefit and at least **10 of the 20 evidence-visible errors persist in C**, with reviewers confirming correct references and recurring, learnable behavior. That supports investigating training; it does not guarantee success or remove the retrieval problem.

For schema errors, supported constrained decoding is another plausible remedy before training. [JSONSchemaBench](https://arxiv.org/abs/2501.10868v1) evaluates schema coverage, generation quality, and efficiency separately: valid structure alone does not establish a correct answer.
