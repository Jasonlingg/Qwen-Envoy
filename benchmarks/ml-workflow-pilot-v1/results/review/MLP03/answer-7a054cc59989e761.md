**Test a non-training fix first.** The hypothetical baseline is 150/200 = **75% passing**. Of 50 failures, 40% lack evidence, 40% answer incorrectly despite visible evidence, and 20% violate the schema. Those labels identify symptoms; they do not establish that fine-tuning will fix them. In particular, evidence visibility does not establish that the model used it successfully.

Separate retrieval and generation diagnosis is supported by [RAGChecker](https://arxiv.org/abs/2408.08067v2). [Lost in the Middle](https://arxiv.org/abs/2307.03172v1) demonstrates that evidence position and context length can affect answering. These studies motivate a diagnostic experiment; their models and benchmarks do not predict this assistant’s improvement.

**Propose one bounded, paired diagnostic experiment—without training.** Use all 50 development failures plus 20 randomly selected development passes as regression controls. Preserve the 100 untouched evaluation cases for later confirmation. Compare three conditions on the same 70 questions:

| Condition | Configuration | What the comparison tests |
|---|---|---|
| A: baseline | Current prompt, retrieved context and output mechanism | Reproduces current behavior |
| B: inexpensive fix | Same retrieved context; one frozen prompt requiring evidence-grounded answers and explicit handling of insufficient evidence; schema-constrained generation if supported | Whether a practical prompt/output fix suffices |
| C: evidence diagnostic | Same configuration as B, but replace context with independently verified, sufficient source passages, without a reference answer | Whether evidence delivery or context noise remains the bottleneck |

B is a combined practical intervention; this experiment cannot attribute its gains separately to prompting and schema enforcement. C is an oracle diagnostic, not a deployable retrieval improvement.

Constrained decoding merits testing for schema failures, but support for the actual schema and effects on answer quality must be verified. [JSONSchemaBench](https://arxiv.org/abs/2501.10868v1) evaluates those dimensions separately; valid structure does not imply correct content.

Before running, pin the checkpoint, runtime, prompt, decoding settings, corpus/index, schema and dataset revisions. **These are currently unknown**, as are context length, existing prompt quality and constrained-output support. If the original setup cannot be reconstructed, establish a fresh baseline rather than treating 75% as reproducible.

Have a reviewer prepare source-grounded answer rubrics and sufficient passages before seeing experimental outputs. Score outputs blind to condition using:

- Correct, sufficiently complete, source-supported answers.
- Schema validity.
- Joint pass: both content and schema succeed; an unjustified abstention is a failure.
- Paired rescues and regressions, reported separately for each original failure category and the passing controls.

Report counts and uncertainty. This failure-enriched sample cannot provide a representative overall pass rate.

- If B rescues at least **10/20 evidence-visible answer failures** and **8/10 schema failures**, with at most one regression among the 20 passing controls, prioritize that non-training fix.
- If C rescues at least **10/20 missing-evidence failures** relative to B, prioritize corpus coverage/retrieval/context delivery. If C also rescues evidence-visible failures, investigate context selection and packing.
- I would change toward considering a **small supervised fine-tuning pilot** if B rescues fewer than **5/20 evidence-visible failures**, at least **10/20 remain incorrect in C**, and review confirms recurring, teachable behavior errors rather than ambiguous questions or faulty reference answers. This would justify a pilot, not establish that training will work.
